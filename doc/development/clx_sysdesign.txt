4. Rule Engine
Purpose
Avoid unnecessary AI calls.

IMPORTANT
Most requests should NOT invoke LLMs.

Example
clx locate help.txt
Should resolve using:
rules/filesystem.yaml
NOT AI.

Rule Structure
intent: find_file

examples:
  - locate help.txt
  - search for file
  - find file recursively

strategies:
  linux:
    command: "find . -name {{filename}}"

  powershell:
    command: "Get-ChildItem -Recurse -Filter {{filename}}"

  cmd:
    command: "dir /s {{filename}}"

Rule Resolution Flow
Input
  ↓
Intent Match
  ↓
OS Detection
  ↓
Command Template
  ↓
Variable Injection
  ↓
Final Command

6. Memory System
IMPORTANT
V1 memory should be:
lightweight session memory ONLY
NOT:
long autonomous agent memory

Memory Purpose
Store:
previous commands 
previous outputs 
aliases 
preferences 
session context 

Example
clx merge feature branch into main
Then:
do the same for release branch
Memory resolves:
previous git strategy 
previous branch flow 

Storage
~/.clx/sessions/

Session Example
{
  "session_id": "abc123",

  "commands": [
    {
      "input": "merge feature branch into main",
      "resolved_command": "git merge feature"
    }
  ]
}

Memory Rules
DO store:
workflow context 
command history 
aliases 

DO NOT store:
entire filesystem knowledge 
massive embeddings 
long-term autonomous planning 
Keep lightweight.

Final Architecture Philosophy
CLX should behave like:
A smart shell abstraction layer
NOT:
an uncontrolled AI agent

Key Success Factors
Must Be:
✅ fast
✅ predictable
✅ explainable
✅ safe
✅ lightweight
✅ cross-platform

Biggest Mistakes To Avoid
❌ full autonomous agents too early
❌ overusing LLMs
❌ giant hardcoded command lists
❌ long-term memory complexity
❌ unsafe auto-execution
❌ slow response times

Final V1 Goal
A developer should be able to type:
clx locate help.txt
and instantly get:
correct native command 
explanation 
safe execution 
on ANY supported shell/OS.
