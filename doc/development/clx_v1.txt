Core Execution Flow
Example
clx grep errors logs.txt

Step 1 — Parse Input
Determine:
raw command 
natural language 
partial shell command 
broken command 

Step 2 — Intent Resolution
Map to semantic intent:
{
  "intent": "search_text_in_file"
}

Step 3 — Environment Resolution
Detect:
{
  "os": "windows",
  "shell": "powershell",
  "tools": [
    "git",
    "docker",
    "node"
  ]
}

Step 4 — Capability Resolution
Find best supported strategy:
Select-String 
findstr 
rg 
grep 

Step 5 — Command Generation
Generate native command:
Select-String "errors" logs.txt

Step 6 — Risk Analysis
{
  "risk": "low"
}

Step 7 — Execute
Execute? [Y/n]

Intent-Based Rule System
IMPORTANT:
Store intents.
NOT raw command mappings.

Example Rule
filesystem.yaml
intent: find_file

examples:
  - locate help.txt
  - find file help.txt
  - search for help.txt

strategies:
  linux:
    primary: "find . -name {{filename}}"

  powershell:
    primary: "Get-ChildItem -Recurse -Filter {{filename}}"

  cmd:
    primary: "dir /s {{filename}}"

Safety Architecture
Safety Levels
Level 0 — Explain only
No execution.

Level 1 — Safe execution
Allowed:
ls 
grep 
cat 
git status 

Level 2 — Moderate
Allows:
installs 
git operations 
docker commands 
Confirmation required.

Level 3 — Full
Almost unrestricted.
Still blocks:
destructive OS-level operations 

Policy Engine
policy.yaml
blocked:
  - "rm -rf /"
  - "shutdown"
  - "format"

allowed:
  - "git"
  - "docker"
  - "npm"

Risk Engine
Every generated command gets classified:
{
  "risk": "medium",
  "reason": "Deletes files recursively"
}

Dry Run Mode
clx cleanup temp files

Will execute:
rm -rf ./temp/*

Affected files: 82
Risk: Medium

Proceed? [Y/n]

Explainability Layer
clx grep errors logs.txt
Outputs:
Intent:
Search text inside files

Translated for PowerShell:
Select-String "errors" logs.txt
This builds trust.
